# Release procedure (v0.5.1+)

One release = one signed tag whose tree contains the checksum manifest for
the binaries that tag ships. The manifest and the binaries travel different
trust paths: binaries are GitHub release assets, the manifest is a committed
file covered by the tag signature.

1. **Green main.** `bun test`, `bun run pty-smoke`, `bun run build --all`,
   `--selftest` on the built binary — per the milestone's GATES ledger.
2. **Build the matrix.** `bun run build --all` produces
   `dist/skills-ui-<ver>-<os>-<arch>` plus `dist/checksums-<ver>.txt`
   (regenerated by `scripts/build.ts`, shasum-compatible).
3. **Commit the manifest.** `cp dist/checksums-<ver>.txt checksums/checksums-<ver>.txt`
   and commit it (`release: checksums <ver>`). The manifest is a data file —
   it is not part of the compile — so binaries built from the parent commit
   are exactly the binaries this tree's manifest describes.
4. **Tag.** `git tag -s v<ver>` on the manifest commit. `git tag -v v<ver>`
   now verifies the manifest together with the tree.
5. **Publish.**
   `gh release create v<ver> dist/skills-ui-<ver>-* dist/checksums-<ver>.txt`
   with release notes. Attach the same manifest file that was committed.
6. **Hosted page.** Web-facing releases also re-export `docs/app.html`
   (`bun run export:page`) and commit it before tagging — Pages serves
   `main/docs`, so the push deploys.
7. **Verify (gate).** From a clean directory:
   - `curl -fsSL https://raw.githubusercontent.com/s-a-c/skills-ui/v<ver>/scripts/install.sh | sh -s v<ver>`
     installs and checksum-verifies (the script prefers the tag-committed
     manifest under `checksums/`).
   - `shasum -a 256 <downloaded-binary>` matches the line in the release
     asset *and* in the tag-committed manifest.

Asset-name reminder: release filenames drop the tag's leading `v`
(`skills-ui-0.5.1-*`, tag `v0.5.1`).

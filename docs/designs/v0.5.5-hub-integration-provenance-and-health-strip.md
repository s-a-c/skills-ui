# skills-ui v0.5.5 — Hub Integration, Provenance Guardrails & Read-Only Health Strip

*   **Author:** s-a-c
*   **Status:** Ratified (`S-313`)
*   **Date:** `2026-11-25`

--------------------------------------------------------------------------------

## Overview

`skills-ui` provides an OpenTUI terminal application (`skills-ui`), a local web dashboard (`--web` and the hosted GitHub Pages frontend paired with `serve`), and a local HTTP API (`serve`) over the stock `skills` CLI. Version `0.5.5` bridges `skills-ui` cleanly with curated multi-harness skill hubs (such as `~/.config/agents/`) while keeping the `skills-ui` codebase strictly public, generic, and free of personal dotfile coupling.

Version `0.5.5` delivers four coordinated capabilities plus companion home-hub wiring:

1. **Global Lockfile Resolution Fix (`src/core/services/locks.ts`):** Prefer `$XDG_STATE_HOME/skills/.skill-lock.json` (`~/.local/state/skills/.skill-lock.json`) and fall back to `skills-lock.json` only when `.skill-lock.json` is absent.
2. **Skill Provenance Taxonomy & Removal Guardrail (`CONTEXT.md` + WebUI + TUI):** Classify every installed skill as `locked`, `linked`, or `local` from `lstat(skill.path)` and `readLock(scope)`, render provenance badges and filter controls, and require explicit confirmation before `rm` deletes any `linked` or `local` skill.
3. **Host-Env Post-Mutation Hook (`SKILLS_UI_POST_MUTATION_HOOK`):** Invoke a host-environment executable directly via `Bun.spawn` (no shell, `30s` timeout) after successful `install`, `remove`, or `update` mutations, surfacing non-zero exits or timeouts as non-fatal warning toasts and `hook` telemetry.
4. **Read-Only Health Strip (`SKILLS_UI_HEALTH_CMD` + `GET /api/health-check` + `Health Pill`):** Poll a host-environment health script (`10s` TTL cache, `15s` timeout, no shell), gate it under full `0.5.1` Host/CORS/Bearer security, advertise capability booleans via `GET /api/version`, and display a compact header `Health Pill` (hidden when unset) across WebUI and TUI.

## The Problem

1. **Blind Global Update Checks:** Stock `skills` (`v1.9.0`) writes `~/.local/state/skills/.skill-lock.json` (leading dot, singular), whereas `globalLockPath()` in `src/core/services/locks.ts` reads `skills-lock.json`. Consequently, `checkForUpdates("global")` sees zero locked skills and skips real upstream checks.
2. **Silent Hub Guard Collisions:** When a user installs or removes a global skill from `skills-ui`, `skills add -g` writes directly to `~/.agents/skills/` without updating an external allowlist manifest or projecting custom host symlink trees. Subsequent `sync-agent-host-links.sh` or `composer` runs abort on untracked additions.
3. **Unprotected Deletion of Symlinked and Local Skills:** `skills rm -g` treats symlinked framework skills (`superpowers`, `egm`) and locally tracked skills (`chezmoi`, custom `s-a-c-*`) identically to `skills`-managed registry skills, risking accidental deletion without warning.
4. **Zero Parity Visibility in UI:** Neither the WebUI nor the TUI exposes whether downstream harness projections match the canonical hub, forcing manual terminal checks after changes.

## Goals

*   **G1 — Accurate Global Lock Resolution:** Read `.skill-lock.json` first in `globalLockPath()`, fall back to `skills-lock.json` only when `.skill-lock.json` is absent, and preserve `InvalidLockFileError` on corrupt JSON or invalid container shapes.
*   **G2 — Visible Skill Provenance & Safe Removal:** Compute `provenance` (`locked` | `linked` | `local`) for every `InstalledSkill`, display compact badges and filter options in WebUI and TUI, and gate `rm` on `linked`/`local` skills behind explicit user confirmation.
*   **G3 — Env-Only Post-Mutation Hook:** Support `SKILLS_UI_POST_MUTATION_HOOK` exclusively from host process env (never HTTP or `prefs.json`), run it directly without a shell after `install`/`remove`/`update`, keep the CLI mutation intact on failure, and surface sanitized failure details via toast + API `hook` field.
*   **G4 — Env-Only Health Check & Header `Health Pill`:** Support `SKILLS_UI_HEALTH_CMD` exclusively from host process env, serve `GET /api/health-check` (`{ ok, summary, details? }`, `10s` cache, bypassed on `?refresh=1` or post-mutation) under full `0.5.1` auth/Host/CORS/rate-limit enforcement, expose `capabilities: { healthCheck, postMutationHook }` booleans in `GET /api/version`, and render a compact header `Health Pill` (hidden when unset) with click / `H` details toggle.
*   **G5 — Strict OSS / Personal Hub Separation:** Keep `skills-ui` 100% generic (plus removing retired `caveman` from `AGENTS.md` and cleaning repo `.ijfw/` leftovers), while wiring `~/.config/agents/bin/skills-ui-post-hook.sh`, `sync-agent-host-links.sh --check`, and shell env vars in companion task `S-319`.

## Non-Goals

*   **NG1:** Hardcoding `chezmoi`, `sync-agent-host-links.sh`, Superpowers/EGM paths, or personal 10-harness layouts inside `skills-ui`.
*   **NG2:** Allowing the WebUI, hosted page, `PUT /api/prefs`, or HTTP query parameters to set, override, or read the filesystem paths of `SKILLS_UI_POST_MUTATION_HOOK` or `SKILLS_UI_HEALTH_CMD`.
*   **NG3:** Making `SKILLS_UI_POST_MUTATION_HOOK` transactional or rolling back `skills add`/`rm`/`update` when a hook fails.

## Ratified Decisions (`S-313` / `D1`)

All six design questions (`Q1`–`Q6`) were ratified in [0.5.5 D1 (`S-313`)](https://linear.app/s-a-c/issue/S-313/055-d1-ratify-global-lockfile-resolution-skill-provenance-guardrails):

1. **Q1 (`globalLockPath`):** Prefer `.skill-lock.json`, fall back to `skills-lock.json` when absent, and preserve `InvalidLockFileError`.
2. **Q2 (`Skill Provenance`):** Classify skills as `locked` / `linked` / `local`, show badges + provenance filter, and require explicit confirmation before `rm` on `linked` or `local` skills.
3. **Q3 (`SKILLS_UI_POST_MUTATION_HOOK`):** Host-env executable, `Bun.spawn([hookPath])` without shell, `30s` timeout, passes `SKILLS_UI_EVENT`, `SKILLS_UI_SCOPE`, `SKILLS_UI_SKILLS`, `SKILLS_UI_CWD`, non-fatal warning toast + `hook` response object on error.
4. **Q4 (`SKILLS_UI_HEALTH_CMD` & `Health Pill`):** Host-env executable, `GET /api/health-check` (`10s` TTL cache, `15s` timeout, no shell) returning `{ ok, summary, details? }`, compact header `Health Pill` hidden when unset, auto-refreshes after mutations, toggles details on click / `H`.
5. **Q5 (`0.5.1` Security):** `GET /api/version` returns capability booleans only (`capabilities.healthCheck`, `capabilities.postMutationHook`). `GET /api/health-check` enforces Host allowlist, CORS origin allowlist, cross-site check, rate limiter, and Bearer token.
6. **Q6 (OSS/Home Boundary):** Generic OSS in `phase/0.5.5` (`S-314`–`S-318`), personal hub bridge in `S-319` verified end-to-end against the built `0.5.5` binary.

## Critical User Journeys (CUJs)

### CUJ 1: Updating Locked Global Skills Without Drift

*   **Given**: The user has `44` global skills in `~/.local/state/skills/.skill-lock.json` and `SKILLS_UI_POST_MUTATION_HOOK` + `SKILLS_UI_HEALTH_CMD` configured.
*   **When**: The user opens `skills-ui` (TUI or WebUI) and triggers update checks or runs `Update`.
*   **Then**: `checkForUpdates("global")` reads `.skill-lock.json` accurately (`checkedCount === 44`), `update` applies upstream changes, the post-mutation hook re-runs guarded host link projection, and the header `Health Pill` refreshes to confirm `ok: true`.

### CUJ 2: Inspecting Provenance & Safely Attempting Removal of Non-Locked Skills

*   **Given**: The global hub contains `locked` skills, `linked` symlinks (e.g., Superpowers `test-driven-development`), and `local` skills (e.g., `unlazy`, `s-a-c-*`).
*   **When**: The user views the `Filter List Panel`, filters by provenance, or presses Remove on a selection containing a `linked` or `local` skill.
*   **Then**: Each `Filter List Card` and `Detail Panel` shows its `Skill Provenance` badge (`locked` / `linked` / `local`), and `Remove` displays an explicit warning naming the non-locked skills before spawning `skills rm`.

### CUJ 3: Installing a New Global Skill Through the Hub Guard

*   **Given**: `SKILLS_UI_POST_MUTATION_HOOK` points to `~/.config/agents/bin/skills-ui-post-hook.sh`.
*   **When**: The user installs a global skill via WebUI or TUI.
*   **Then**: `skills add --global` succeeds, `skills-ui` runs `SKILLS_UI_POST_MUTATION_HOOK` with `SKILLS_UI_EVENT=install` and `SKILLS_UI_SCOPE=global`, the hook updates the hub manifest and projects symlinks across all host trees, and the `Health Pill` refreshes cleanly. If the hook fails, the UI displays a warning toast with sanitized stderr/exit code.

### CUJ 4: Running Vanilla `skills-ui` Without Hooks or Health Command

*   **Given**: Neither `SKILLS_UI_POST_MUTATION_HOOK` nor `SKILLS_UI_HEALTH_CMD` is set in the host environment.
*   **When**: Any external user launches `skills-ui`, `skills-ui --web`, or `skills-ui serve`.
*   **Then**: `GET /api/version` reports `capabilities: { healthCheck: false, postMutationHook: false }`, the `Health Pill` stays completely hidden, `GET /api/health-check` returns `{ ok: true, configured: false, summary: "not configured" }`, and mutations perform zero extra spawns.

## Technical Architecture

```text
Host Process Env (never HTTP / prefs.json)
  |-- SKILLS_UI_POST_MUTATION_HOOK = /path/to/hook-exe
  |-- SKILLS_UI_HEALTH_CMD         = /path/to/health-exe
  v
skills-ui Core (src/core/services/ + src/core/api.ts)
  |-- locks.ts:      globalLockPath() -> .skill-lock.json ?? skills-lock.json
  |-- installed.ts:  lstat(path) + readLock() -> provenance: locked | linked | local
  |-- hooks.ts:      Bun.spawn([exe]) direct (no shell, sanitized output, timeouts)
  |     |-- runPostMutationHook() -> { ok, skipped?, exitCode?, summary, output? }
  |     +-- checkHealth()         -> 10s TTL cache -> { ok, configured, summary, details? }
  |-- GET /api/version       -> { version, skillsVersion, capabilities }
  +-- GET /api/health-check  -> Host/CORS/Bearer gated -> HealthCheckResult
  v
WebUI (src/web/page.ts -> docs/app.html) & TUI (src/tui/{model,app,Views}.tsx)
  |-- Filter List Card / Detail Panel: Skill Provenance badges + filter
  |-- Remove Action:                   Confirmation guardrail for linked / local skills
  |-- Post-Mutation:                   Warning toast if hook.ok === false + refresh Health Pill
  +-- Header Bar:                      Compact Health Pill (hidden if !capabilities.healthCheck)
```

### 1. Lockfile & Skill Provenance (`src/core/services/locks.ts`, `installed.ts`, `types.ts`)

*   `globalLockPath()`: Resolve `base = process.env.XDG_STATE_HOME ? join(process.env.XDG_STATE_HOME, "skills") : join(homedir(), ".local", "state", "skills")`. Return `join(base, ".skill-lock.json")` if `existsSync(...)` or if `join(base, "skills-lock.json")` does not exist, else return `join(base, "skills-lock.json")`.
*   `SkillProvenance`: Export `type SkillProvenance = "locked" | "linked" | "local"`.
*   Classification order in `listInstalled(scope)`:
    1. Call `lstatSync(skill.path)` inside `try/catch`. If `stats.isSymbolicLink()`, assign `"linked"`.
    2. Else check `Object.hasOwn(lock.skills, skill.name)`. If present, assign `"locked"`.
    3. Otherwise assign `"local"`.
    *(Note: symlinked directories always classify as `"linked"` even if listed in the lockfile, preventing `rm` from silently unlinking managed framework projections without warning.)*

### 2. Env-Only Hooks & Health Service (`src/core/services/hooks.ts` + `src/core/api.ts`)

*   **Environment Isolation (`src/core/skills-client.ts`):** `sanitizeEnv()` continues forwarding `SKILLS_*` ONLY to `skills-ui` child hooks as explicit `SKILLS_UI_EVENT`, `SKILLS_UI_SCOPE`, `SKILLS_UI_SKILLS` (comma-separated skill names), and `SKILLS_UI_CWD`. Strip `SKILLS_UI_POST_MUTATION_HOOK` and `SKILLS_UI_HEALTH_CMD` from `sanitizeEnv()` used by stock `skills` CLI subprocesses so the child `skills` CLI cannot recurse into `skills-ui` hooks.
*   **`runPostMutationHook(opts)`:**
    *   Reads `process.env.SKILLS_UI_POST_MUTATION_HOOK?.trim()`. If unset, returns `{ configured: false, ok: true, skipped: true }`.
    *   Spawns `Bun.spawn([hookPath], { cwd: opts.cwd, env, stdin: "ignore", stdout: "pipe", stderr: "pipe" })` with a `30_000 ms` timeout (`proc.kill()` on expiry). Never invokes `/bin/sh -c`.
    *   Captures stdout/stderr (capped and sanitized via `sanitizeMetadata`), returning `{ configured: true, ok: exitCode === 0 && !timedOut, exitCode, timedOut, summary, output }`.
*   **`checkHealth({ refresh?: boolean })`:**
    *   Reads `process.env.SKILLS_UI_HEALTH_CMD?.trim()`. If unset, returns `{ configured: false, ok: true, summary: "not configured", checkedAt }`.
    *   Caches result in-memory for `10_000 ms` (bypassed when `refresh === true` or invalidated by `invalidateHealthCache()` after any mutation).
    *   Spawns `Bun.spawn([healthCmd], { stdin: "ignore", stdout: "pipe", stderr: "pipe" })` with a `15_000 ms` timeout.
    *   Parses stdout JSON expecting `{ ok: boolean, summary: string, details?: string[] }`. Sanitizes `summary` and `details` via `sanitizeMetadata`. On non-zero exit, timeout, or invalid JSON, returns `{ configured: true, ok: false, summary: "health check failed", details: [sanitizedOutput] }`.
*   **HTTP Endpoints (`src/core/api.ts`):**
    *   `GET /api/version`: Add `capabilities: { healthCheck: isHealthCmdConfigured(), postMutationHook: isPostMutationHookConfigured() }`. Never return command paths.
    *   `GET /api/health-check`: Enforces existing Host/origin/cross-site/rate-limit/Bearer checks. Accepts `?refresh=1`. Calls `checkHealth({ refresh })` and returns JSON `200` (or `500` only on unexpected internal faults).
    *   `POST /api/install`, `POST /api/remove`, `POST /api/update`: When `ok === true`, invalidate health cache, call `runPostMutationHook(...)`, and attach `hook` to the response payload when configured.

### 3. WebUI & TUI Surfaces (`src/web/page.ts`, `src/tui/{model,app,Views}.tsx`)

*   **WebUI (`src/web/page.ts`):**
    *   Render a compact `<span class="prov-badge prov-${s.provenance}">` (`locked` / `linked` / `local`) on each Installed card and inside `#detailPane`, plus a provenance filter select/chip row inside `#listPane` (`flex-wrap:wrap`).
    *   Before calling `POST /api/remove`, inspect selected skills: if any have `provenance !== "locked"`, show an explicit confirmation dialog listing their names and provenance (`linked` / `local`) before sending the request.
    *   Display a compact `<button id="healthPill" class="health-pill" hidden>` in the header when `capabilities.healthCheck` is true, showing status dot + sanitized `summary`. Clicking opens a lightweight popover listing `details` + a `Refresh` button (`GET /api/health-check?refresh=1`).
    *   After `install`, `remove`, or `update`, toast `hook.summary` as a warning if `hook?.configured && !hook.ok`, and refresh `#healthPill` if enabled.
*   **TUI (`src/tui/{model,app,Views}.tsx`):**
    *   Add `provenanceFilter: "all" | SkillProvenance` (`p` cycles or `InstalledBody` filter), `healthCapability: boolean`, `health: HealthCheckResult | null`, `healthOpen: boolean`, and `confirmNonLockedRemove: { names: string[]; nonLocked: InstalledSkill[] } | null` to `TuiModel`.
    *   Wire `runPostMutationHook` and `checkHealth` into `TuiDeps` (injected in `realDeps`, mockable in `tests/tui.test.ts`).
    *   Render provenance badge (`[lnk]` / `[loc]` / `[lck]` or short tag fitting single-line `height={1}` rows) in `InstalledBody` and full provenance label in `Detail Panel`.
    *   Gate `r` / `x` removal on `linked`/`local` skills with an explicit confirmation prompt (`y` confirms, `n`/`Esc` cancels).
    *   Render a compact `Health Pill` in the TUI header when `healthCapability` is true (`H` toggles details / refreshes).

## Non-Functional Requirements

*   **Security & CSP Integrity:** Executable paths stay strictly in host environment variables, never exposed in `/api/version`, `/api/health-check`, `docs/app.html`, or `prefs.json`. Regenerate `docs/app.html` via `bun run export:page` after editing `src/web/page.ts` so `pageCspFor()` SHA-256 hashes match `tests/page-hardening.test.ts`.
*   **Performance Budgets:** `lstat` runs once per installed skill during `listInstalled` (already cached in `serve` and SWR-cached in TUI). Keep all 11 rows of `bun run perf:budget -- --strict` passing.
*   **Backward Compatibility & Rollback:** Unset env vars preserve exact `0.5.4.1` runtime behavior (`Health Pill` hidden, zero hook spawns). Rollback is a clean revert of the `0.5.5` merge commit.

## Alternatives Considered

### Alternative A: Configure Hook and Health Commands in `~/.config/skills-ui/prefs.json`

*   **Pros**: Users can edit hook paths from the Settings UI or `PUT /api/prefs`.
*   **Cons**: Violates `0.5.1` security boundaries by letting any authenticated browser tab (including the hosted GitHub Pages origin) write arbitrary command paths that `skills-ui` executes on the host.
*   **Reason for Rejection**: Rejected in `S-313` (`Q3`/`Q4`/`Q5`). Reading `SKILLS_UI_POST_MUTATION_HOOK` and `SKILLS_UI_HEALTH_CMD` strictly from the host process environment eliminates remote command-injection risk.

### Alternative B: Shell-Wrap Hook Commands via `/bin/sh -c`

*   **Pros**: Allows inline shell pipelines directly inside the environment variable string.
*   **Cons**: Introduces shell-quoting bugs, interactive alias interference, and injection hazards.
*   **Reason for Rejection**: Rejected in `S-313` (`Q3`/`Q4`). Executing the executable path directly via `Bun.spawn([cmd])` keeps execution deterministic and safe.

### Alternative C: Build Projection and Chezmoi Sync Directly Inside `skills-ui`

*   **Pros**: Eliminates external helper scripts in `~/.config/agents/bin/`.
*   **Cons**: Couples a public MIT tool to personal dotfiles, chezmoi state, and custom 10-harness symlink layouts.
*   **Reason for Rejection**: Rejected in `S-313` (`Q6`). Keeping `skills-ui` generic and isolating personal hub logic in `S-319` (`~/.config/agents/bin/`) preserves both OSS portability and full home-hub automation.

# skills-ui v0.5.4.1 — List-Card Ergonomics & Split-Pane Parity

*   **Author:** s-a-c
*   **Status:** Draft
*   **Date:** 2026-11-08

--------------------------------------------------------------------------------

## Overview

`skills-ui` provides a local web dashboard (`--web` and the static GitHub Pages frontend paired with `serve`) and an OpenTUI terminal application (`skills-ui`) over the `skills` CLI. Version `0.5.4` unified the WebUI around a two-pane workspace (`#listPane` on the left and `#detailPane` on the right) and introduced an adjustable list width.

Version `0.5.4.1` resolves four remaining user-experience and cross-surface consistency gaps between the WebUI and the TUI:
1. Binding the selection checkbox and skill name into an unbreakable inline unit (`Name-Checkbox Unit`) on every `Filter List Card` so line wrapping never separates a checkbox from its label.
2. Expressing the `Filter List Panel` width as a proportional percentage (`10%` to `50%` of the whole `Frame`, defaulting to `35%`) shared between WebUI and TUI, with automatic migration of legacy `v0.5.4` pixel values (`240..640`).
3. Keeping the `Penultimate Card Line` text left-justified while placing card action buttons in a `Contiguous Action Group` that is right-justified on the last line when narrow and merges onto the penultimate line when horizontal space allows.
4. Bringing the TUI to structural and behavioral parity with the WebUI across split-pane Search, `10%–50%` list-pane width controls, 3-mode sorting (`checked` → `name` → `load`), and single-line non-wrapping list rows.

## The Problem

Users operating `skills-ui` across different window widths and switching between the browser UI and terminal UI encounter four concrete friction points:

1. **Detached Checkboxes on Narrow Cards:** In the WebUI Search list (`#results li`), the checkbox input sits outside the card header container inside a column flex layout, forcing the checkbox onto a line above the skill name. On Installed cards (`#skillList li`), narrowing the `Filter List Panel` allows long skill names or trailing badges to wrap or collide with the checkbox, making it hard to tell which checkbox belongs to which skill.
2. **Viewport-Dependent Pixel Widths:** Version `0.5.4` stored `UiPreferences.listWidth` in pixels (`240..640` px). A pixel value does not scale across narrow laptop split-screens, ultrawide monitors, or terminal character grids, and prevents the user from narrowing the `Filter List Panel` down to `10%` or capping it at `50%` of the `Frame`. Furthermore, users upgrading from `0.5.4` have pixel integers (such as `360`) persisted in `~/.config/skills-ui/prefs.json` that would clamp to `50%` if not migrated.
3. **Wasted Vertical Space on Search Cards:** Search cards always stack the repository source line (`owner/repo`) and the action buttons (`+ Add to list`, `Install`) on separate lines with left alignment, even when the `Filter List Panel` is wide enough to fit both on one line. When the panel is narrow, individual action buttons can also wrap apart from one another instead of moving together as a single right-justified block.
4. **TUI / WebUI Split-Brain:** While the WebUI uses a unified two-pane layout (`Filter List Panel` + `Detail Panel`) for both Installed and Search tabs and supports three sort modes (`Checked first`, `A to Z`, `Load order`), the TUI still renders Search as a single full-width box with no `Detail Panel`, hardcodes the Installed list width to `42%`, and only toggles between two sort states (`checked` and `order`).

## Goals

*   **G1 — Unbreakable Name-Checkbox Unit:** Guarantee that the selection checkbox (or TUI check/cursor prefix), status indicator, and skill name never wrap onto separate lines on any `Filter List Card` in either WebUI or TUI, down to a `10%` `Filter List Panel` width.
*   **G2 — Proportional `10%–50%` Filter List Panel Width:** Persist `UiPreferences.listWidth` as an integer percentage in `10..50` (`null` = `35%` default), migrate legacy `v0.5.4` pixel values (`> 50`) to `null`, and drive both the WebUI (`#listSplitter` drag/keyboard and `#settings` range input) and TUI (`InstalledBody` and `SearchBody` left pane width, `[` / `]` / `0` keys, and `SettingsBody` row) from that percentage without horizontal overflow in `#listPane` headers at `10%`.
*   **G3 — Left-Justified Penultimate Line with Merging Contiguous Right-Justified Actions:** Keep text on the `Penultimate Card Line` left-justified and group card action buttons into a non-breaking, right-justified `Contiguous Action Group` that sits on the last line when narrow and merges onto the penultimate line when space allows.
*   **G4 — TUI Parity with WebUI:** Convert TUI `SearchBody` to a two-pane split layout (`Filter List Panel` + `Detail Panel` showing selected search result metadata, install/update state, sibling repository skills, and queue status) while preserving 80-column `pty-smoke` border-title invariants, and support the 3-mode `s` sort cycle (`checked` → `name` → `load`) across both Installed and Search tabs.

## Non-Goals

*   **NG1:** Adding per-card action buttons to Installed cards (`#skillList li`), whose actions remain in the top bar and `Detail Panel`.
*   **NG2:** Modifying the local HTTP API wire endpoints (`/api/*`) or the subprocess invocation contract with the upstream `skills` CLI.
*   **NG3:** Replacing the TUI Search `install list (N)` sub-section with a modal overlay; keeping `Results` and `install list (N)` inside the left `Filter List Panel` scrollbox preserves the `Tab` key contract.

## Open Questions

*   None. All requirements and edge-case mitigations were resolved during `/grill-with-docs` and `/egm-brainstorm` (ratified in Linear decision ticket `S-257`).

## Critical User Journeys (CUJs)

### CUJ 1: Resizing the Filter List Panel Across `10%–50%` Without Breaking Card Anatomy

*   **Given**: The user has `skills-ui` open in the WebUI (`--web` or hosted `docs/app.html`) on either the `Installed` or `Search` tab.
*   **When**: The user drags `#listSplitter` or adjusts `#listWidthRange` in Settings anywhere between `10%` and `50%` of the `Frame` (or double-clicks / presses `0` to reset to `35%`).
*   **Then**:
    1. `--list-col` updates to the integer percentage (`10%`–`50%`) and persists to `~/.config/skills-ui/prefs.json`.
    2. On every `Filter List Card`, the checkbox and skill name remain on the same horizontal line (`Name-Checkbox Unit`), truncating long skill names with an ellipsis while wrapping secondary chips/badges below.
    3. On Search cards, the `Penultimate Card Line` (`.result-source`) remains left-justified, while the `Contiguous Action Group` (`+ Add to list`, `Install`) stays right-justified—merging onto the `.result-source` line at wider percentages and dropping as a single unbroken right-justified unit onto the last line at narrower percentages.

### CUJ 2: Inspecting Search Results and Adjusting Layout & Sort Order in the TUI

*   **Given**: The user launches `skills-ui` in an 80×24 (or wider) terminal and presses `/` to enter the `Search` tab.
*   **When**: The user types a query, navigates results, presses `s` to cycle sort modes, and presses `[` / `]` / `0` in command mode to adjust the `Filter List Panel` width.
*   **Then**:
    1. `SearchBody` renders a two-pane split layout matching `InstalledBody`: the left `Filter List Panel` (`width="${prefs.listWidth ?? 35}%"`) displays `Results` and `install list (N)` with single-line non-wrapping `[✔ ❯ skill-name]` rows, and the right `Detail Panel` displays the selected result's metadata, install/update status, sibling skills in the same repository, and queue status.
    2. Pressing `s` cycles `checked` → `name` → `load` across both `Installed` and `Search`, keeping cursor actions (`Space`, `Enter`) aligned with the visible sorted order.
    3. Pressing `[` or `]` adjusts `prefs.listWidth` in `5%` steps within `10%–50%` (`0` resets to `35%`), persisting to `~/.config/skills-ui/prefs.json`.

## Technical Plan (Architecture)

Version `0.5.4.1` modifies three architectural layers—shared preferences (`src/core/prefs.ts`), WebUI DOM/CSS (`src/web/page.ts` + exported `docs/app.html`), and the Elm-style TUI (`src/tui/model.ts`, `src/tui/app.ts`, `src/tui/Views.tsx`)—without altering the HTTP API wire format or the `skills` CLI subprocess wrapper.

```text

|                       ~/.config/skills-ui/prefs.json                    |
|   listWidth: number (10..50 %) | null (default 35%; >50 px -> null)     |
+------------------------------------+------------------------------------+
                                     |
                   +-----------------+-----------------+
                   |                                   |
                   v                                   v
+------------------------------------+------------------------------------+
|       WebUI (src/web/page.ts)      |    TUI (src/tui/model.ts + Views)  |
+------------------------------------+------------------------------------+
| Frame (<main> CSS Grid):           | Frame (<box flexDirection="row">): |
|   --list-col: ${pct}% (10%..50%)   |   Left pane width: "${pct}%"       |

|   #listWidthRange (10..50, step 1) |   SettingsBody row display         |
|                                    |                                    |
| Filter List Card Anatomy:          | Filter List Card & Split Search:   |
|   .skill-title-unit /              |   Single-line non-wrapping row:    |
|   .result-title-unit:              |     [✔ ❯ skill-name] (height=1)    |
|     [checkbox + dot + name]        |   SearchBody two-pane split:       |

|     .result-actions (nowrap,       |       install/update status,       |

|                                    |   3-mode Sort ('s' key):           |
| 3-mode Sort (.sort-row):           |     checked -> name -> load        |

|                                    |      model.visibleResults)         |
+------------------------------------+------------------------------------+
```

### 1. Shared Proportional List Width & Migration (`src/core/prefs.ts`)

*   **Bounds:** Redefine `LIST_WIDTH_MIN = 10` and `LIST_WIDTH_MAX = 50` (representing integer percentages of the `Frame` width). Keep `DEFAULT_UI_PREFERENCES.listWidth = null`, where `null` resolves to `35%`.
*   **Legacy Pixel Migration in `normalizePreferences()`:**
    *   In `v0.5.4`, `listWidth` stored pixel integers in `240..640`.
    *   When `typeof raw.listWidth === "number" && Number.isFinite(raw.listWidth)`:
        *   Let `rounded = Math.round(raw.listWidth)`.
        *   If `rounded > LIST_WIDTH_MAX` (`> 50`), treat it as a legacy `v0.5.4` pixel value and normalize `prefs.listWidth = null` (`35%` default) rather than clamping to `50%`.
        *   Otherwise clamp `Math.max(LIST_WIDTH_MIN, rounded)` so values `< 10` clamp to `10` and values in `10..50` persist as integers.

### 2. WebUI Card Anatomy & `10%–50%` Resizable Frame (`src/web/page.ts`)

*   **Unbreakable `Name-Checkbox Unit` (`#skillList li` and `#results li`):**
    *   **Installed Cards (`rowHtml(s)`):** Keep `.skill-name` as a wrapping flex container (`display:flex; flex-wrap:wrap; align-items:center; gap:8px; min-width:0`) and group the leading checkbox, status dot, and name text inside `<span class="skill-title-unit">` (`display:inline-flex; align-items:center; gap:8px; flex-wrap:nowrap; min-width:0; max-width:100%; flex:1 1 auto`). Wrap the skill name string inside `<span class="skill-name-text">` (`overflow:hidden; text-overflow:ellipsis; white-space:nowrap; min-width:0`). Leave `<span class="update-badge">update</span>` as a sibling inside `.skill-name` after `.skill-title-unit` so the badge wraps below when narrow while `.skill-check` and `.skill-name-text` never separate.
    *   **Search Cards (`renderResults()`):** Remove the stray `<input class="result-check">` child outside `.skill-main` and place it inside `.result-head` wrapped with `<span class="result-name">` inside `<span class="result-title-unit">` (`display:inline-flex; align-items:center; gap:8px; flex-wrap:nowrap; min-width:0; max-width:100%; flex:1 1 auto`), with `.result-name` styled `font-weight:700; overflow:hidden; text-overflow:ellipsis; white-space:nowrap; min-width:0`. Leave `.result-chip` and `.result-installs` as sibling children inside `.result-head` (`flex-wrap:wrap`) so they wrap below `.result-title-unit` when narrow.
*   **Penultimate Line Left-Justified + Merging Contiguous Right-Justified Actions (`.result-foot`):**
    *   In `renderResults()`, wrap `<span class="result-source">` and `<div class="result-actions">` inside `<div class="result-foot">` (`display:flex; flex-wrap:wrap; align-items:center; gap:8px; min-width:0`).
    *   Style `.result-source` with `text-align:left; margin-right:auto; min-width:0; overflow-wrap:anywhere`.
    *   Style `.result-actions` with `display:inline-flex; flex-wrap:nowrap; gap:8px; margin-left:auto; flex-shrink:0`.
    *   When `.result-source` and `.result-actions` fit on a single row, `.result-actions` sits on the penultimate line flush right while `.result-source` stays flush left. When the card narrows, `.result-actions` wraps as a single unbroken group onto the last line, right-justified via `margin-left:auto`.
*   **Proportional `10%–50%` `#listSplitter` and `#listWidthRange`:**
    *   Set `main` grid template column fallback to `var(--list-col, 35%) 0px 1fr`.
    *   In `applyListWidth(raw)`, set `mainEl.style.setProperty('--list-col', w + '%')` when `w` is in `10..50` (or remove `--list-col` when `w === null`), update `#listSplitter` `aria-valuenow` and `#listWidthRange.value` to `String(w !== null ? w : 35)`, and set `#listWidthValue.textContent` to `w === null ? 'Auto (35%)' : (w + '%')`.
    *   In `#listSplitter` `pointermove`, compute the percentage of `mainEl.getBoundingClientRect()` (`((ev.clientX - rect.left) / rect.width) * 100`) and pass to `clampListWidth()`.
    *   In `#listSplitter` `keydown`, step by `1%` (`5%` with `Shift`) on `ArrowLeft` / `ArrowRight`, jump to `10` on `Home` and `50` on `End`, and reset to `null` (`35%`) on `0`, `Backspace`, or `Delete`.
    *   To prevent horizontal overflow inside `#listPane` at `10%` width, add `flex-wrap:wrap; min-width:0` to `.filter-row`, `.sort-row`, `.sort-row .seg`, and `.list-head`.

### 3. TUI Parity (`src/tui/model.ts`, `src/tui/app.ts`, `src/tui/Views.tsx`)

*   **3-Mode Sort Cycling & `model.visibleResults` (`src/tui/model.ts`):**
    *   Define `export type SortMode = "checked" | "name" | "load";` and add `sortBy: SortMode` (default `"checked"`) and `visibleResults: SearchSkill[]` (default `[]`) to `TuiModel`.
    *   Synchronize `sortCheckedFirst: boolean` with `sortBy` on `sort-toggle` (`"checked"` → `"name"` → `"load"` → `"checked"`). In `visibleSkills(model)`, if a caller mutates `model.sortCheckedFirst = false` directly while `model.sortBy === "checked"` (used by `tests/filter-parity.test.ts`), treat effective sort as `"load"`.
    *   Add `visibleSearchResults(model)` and memoize it into `next.visibleResults` inside `update()` (capped at `SEARCH_RENDER_CAP` for cursor clamping):
        *   `"checked"`: queued skills (`model.queue.has("${r.source}#${r.name}")`) first, preserving registry order within each group.
        *   `"name"`: `a.name.localeCompare(b.name)`.
        *   `"load"`: `b.installs - a.installs` (matching WebUI `sortedResults()`).
    *   All Search cursor readers (`move`, `home`, `end`, `space` queue toggle, `return` single-skill install) read `model.visibleResults` instead of raw `model.results`.
*   **Two-Pane Split `SearchBody` & Source Sibling Discovery (`src/tui/Views.tsx`, `src/tui/app.ts`):**
    *   Add `sourceSkills: Record<string, SourceSkill[]>` to `TuiModel` (updated via `{ type: "source-skills-loaded"; source: string; skills: SourceSkill[] }`) and optional `listSourceSkills?: (source: string) => Promise<SourceSkill[]>` to `TuiDeps` (wired in `realDeps` to `svcListSourceSkills` from `../core/index.ts`).
    *   Restructure `SearchBody` into a two-pane row (`flexDirection="row" gap={1} paddingLeft={1} paddingRight={1}`):
        *   **Left `Filter List Panel` (`width="${model.prefs.listWidth ?? 35}%"`):** Bordered rounded box containing the `scrollbox` with `Results` and `install list (${model.queue.size})`.
        *   **80-Column `pty-smoke` Border Title Guard:** At `35%` of an 80-column terminal (`27` cols), the border title budget is ~23 characters. Format the left pane border title as `` ` search: ${model.query}${model.query && model.searching ? "▌" : ""} ` `` when appending `· ${model.results.length} results` would exceed 22 characters, and render `${model.results.length} results${model.adjustedQuery && model.query ? ` · showing "${model.adjustedQuery}"` : ""} · ${model.sortBy}` on the `Results` section header inside the scrollbox so `smoke.py` (`app.find("search: cli-an") == 1` and `app.find("120 results") >= 0`) and `tests/tui.test.ts` (`showing "cli-ansi"`) always pass.
        *   **Right `Detail Panel` (`flexGrow={1} flexShrink={1}`):** Bordered rounded box displaying the focused search result (`r = resultsActive ? model.visibleResults[model.searchSelected] : [...model.queue.values()][model.selectedCursor] ?? model.visibleResults[model.searchSelected]`): name, `source: ${r.source}`, `installs: ${r.installs}`, target scope (`scope: ${model.scope}`), installed/update status across `model.skills`, queue status (`✓ in install list` vs `space/+ to add`), and sibling skills discovered in `r.source`.
*   **Adjustable Left-Pane Width (`10%–50%`) & Single-Line Non-Wrapping Rows:**
    *   Bind `InstalledBody` and `SearchBody` left-pane `width` to `` `${model.prefs.listWidth ?? 35}%` ``.
    *   In `InstalledBody`, adapt `listTitle` when `listWidth < 30` so the border title never overflows narrow panes while keeping `" ${visible.length} skills·${sortLabel}"` (`checked` / `name` / `order`) intact at the default `35%` width on 80-column terminals.
    *   In `src/tui/app.ts` command mode, bind `[` (`-5%`), `]` (`+5%`), and `0` (reset to `null` = `35%`) to update `model.prefs.listWidth` within `[LIST_WIDTH_MIN, LIST_WIDTH_MAX]` and persist via `deps.savePrefs(prefs)`.
    *   Add `["[ / ]  list width", ...]` to `SettingsBody`.
    *   On all list rows in `InstalledBody` and `SearchBody`, set `height={1}` and `overflow="hidden"` with `[✔ ❯ skill-name]` grouped so the check/cursor prefix and skill name never wrap onto separate lines.

## Non-Functional Requirements

*   **Security & CSP Integrity:** `src/web/page.ts` pins SHA-256 hashes of `bootstrapScript` and `APP_JS` in `pageCspFor()`. Every edit to `src/web/page.ts` must be followed by `bun run export:page` so `docs/app.html` and `tests/page-hardening.test.ts` stay hash-valid.
*   **Performance Budgets:** Keyed DOM reconciliation (`rowByKey` and `rowSignature` in `src/web/page.ts`) and per-dispatch memoization (`model.visible` and `model.visibleResults` in `src/tui/model.ts`) must keep all 11 rows of `bun run perf:budget -- --strict` passing.
*   **Backward Compatibility & Rollback:** `normalizePreferences()` migrates legacy `v0.5.4` pixel values (`> 50`) to `null` (`35%`) automatically. Rollback is a clean revert of the `0.5.4.1` merge commit.

## Alternatives Considered

### Alternative A: Clamp Legacy `v0.5.4` Pixel `listWidth` Values (`240..640`) to `LIST_WIDTH_MAX` (`50%`)

*   **Pros**: Requires zero migration branch inside `normalizePreferences()` beyond changing `LIST_WIDTH_MIN = 10` and `LIST_WIDTH_MAX = 50`.
*   **Cons**: Every user upgrading from `v0.5.4` who dragged the splitter or used the Settings slider has a pixel value in `240..640` stored in `~/.config/skills-ui/prefs.json`. Simple clamping would pin every upgraded user at the maximum `50%` width instead of the `35%` default.
*   **Reason for Rejection**: Rejected by author: normalizing values `> 50` to `null` (`35%` default) in `normalizePreferences()` prevents existing pixel preferences from distorting the layout after upgrade.

### Alternative B: Use a JavaScript `ResizeObserver` to Toggle `.result-actions` Between Lines

*   **Pros**: Allows explicit DOM class toggling when the card width crosses a measured pixel threshold.
*   **Cons**: Attaching or running a `ResizeObserver` across up to 200 search result cards introduces layout measurement overhead during splitter dragging and duplicates behavior that CSS Flexbox handles natively.
*   **Reason for Rejection**: Rejected by author: wrapping `.result-source` (`margin-right:auto; min-width:0`) and `.result-actions` (`display:inline-flex; flex-wrap:nowrap; margin-left:auto; flex-shrink:0`) inside a single `display:flex; flex-wrap:wrap` container (`.result-foot`) achieves the exact merge-or-wrap layout declaratively with zero JavaScript layout thrash.

### Alternative C: Replace the TUI Search `install list (N)` Sub-Section with a Modal Overlay

*   **Pros**: Frees vertical rows inside the left `Filter List Panel` scrollbox when `SearchBody` becomes a two-pane split view.
*   **Cons**: Breaks the `Tab` key sub-pane switching contract (`results` ↔ `selected`) in `src/tui/model.ts` and invalidates the `scripts/pty-smoke/smoke.py` assertions (`❯ install list (2)`).
*   **Reason for Rejection**: Rejected by author: keeping `Results` and `install list (N)` stacked inside the left `Filter List Panel` scrollbox while adding the right `Detail Panel` delivers split-pane parity with the WebUI without breaking TUI keyboard navigation or `pty-smoke`.
